# 规范批准的来源追溯

0074 增加 AC 和业务规则批准修订到固定来源的依赖登记。它补充自主系统画像的规范依据追溯，不产生新的批准，不替代原文、私有归档、角色或来源权限检查。验证状态见[实施记录](./implementation-progress.md)。

## 固定依赖

`requirement_authority_provenance` 的每条记录固定一种原生批准修订，包括 approved、withdrawn 和重新批准：

- 同项目的 AC 或业务规则修订、原元数据摘要、私有工件摘要和 canonical invocation。
- 原 image revision/hash、来源 binding/revision、原文子对象 document revision、依据摘要。
- 0070 对象来源图中 image_objects、member、document 的确切节点及 registration hash；源原文证据和需求父对象沿原图追溯。
- 同一规范身份的完整前驱修订与前驱 registration hash，不替换为最新批准头。

AC 与业务规则是不同类型和原生 FK，不能相互冒充。记录只含 ID、摘要和状态，不复制源码、oracle、审阅理由、私有存储地址或凭据。source、manifest、文档、证据、画像和既有 ContextPack 的摘要均保持原样。

## 写入与读取

原确认命令在项目锁内校验来源、角色和前驱，保存规范事实后登记新的当前修订；已有前驱只允许核验，不允许补造。登记、原事实及 Outbox 仍处于同一 PG 事务。事件追加再次只读核验整个历史，即使来源事件已经清理也不能通过重放补登记。缺失、错误摘要、错误端点或前驱使整个提交失败。

规范 history/get、已提交命令恢复和后续改判都只读核验登记。ContextPack 的既有 authority application port 因而核验所消费的批准历史；v3 及以后策略包含独立业务规则批准，v1/v2 的旧规则语义不变。归档仍保留当时批准 pin，后来撤回会使当前使用失效，不改写原历史正文，也不增加生成或执行许可。

规范详情的原文检查使用单次操作内的画像只读快照：首次完整核验后，固定成员、原文和证据检查复用同一画像；在 ContextPack 编译内则复用该编译已有的快照。下一次独立请求重新核验，不缓存批准头或权限。详情中的 current 使用已核验的同一来源依据验证原规范工件，不再次重读相同来源；历史 GET 仍独立核验。当前角色和来源权限继续实时复查，坏工件仍拒绝返回。这是减少重复校验，不是跨请求缓存或性能门禁完成。
